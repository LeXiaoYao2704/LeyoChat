# LeyoChat

LeyoChat is a Windows-first desktop communication client built with C++20,
Qt 6, and CMake. It supports LAN peer-to-peer messaging and an optional
self-hosted service for durable delivery, offline synchronization, group
messaging, and shared files.

The default configuration is `P2POnly`. A fresh client has no built-in server
address or credential and does not contact a LeyoChat message service until the
user explicitly configures one.

## Status

- Current source version: `0.4.0`
- Primary platform: Windows 10/11 x64
- Primary toolchain: Visual Studio 2022 with Qt 6.6.3
- Project stage: pre-release open-source preparation

The repository contains production-derived code and a large test surface, but
the complete legacy test matrix is not yet green. Focused builds and tests must
not be treated as proof that every optional integration works.

## Features

- LAN discovery and direct P2P text messaging
- Direct and group conversations
- Images, files, screenshots, replies, mentions, reactions, and read receipts
- Optional durable message and file service
- Client launcher and Windows service host with crash recovery
- Optional ONLYOFFICE/WOPI document integration
- Optional Azure DevOps and Outlook/EWS notifications
- Local SQLite persistence and diagnostic export

## Routing modes

| Mode | Behavior |
| --- | --- |
| `P2POnly` | Uses LAN discovery and direct peer connections. No message service is required. |
| `ServerPreferred` | Uses the configured service when available and can fall back to P2P according to policy. |
| `ServerOnly` | Requires the configured service and does not use P2P delivery fallback. |

Large deployments should avoid automatic full-mesh P2P connections. Deployment
limits and capacity guidance are documented in
[`docs/service-deployment.md`](docs/service-deployment.md).

## Requirements

- CMake 3.24 or newer
- Visual Studio 2022 Build Tools with the x64 C++ workload
- Qt 6.6.3 MSVC x64 with `Widgets`, `Network`, `Sql`, `Concurrent`,
  `Multimedia`, and `Test`
- Optional Qt modules:
  - `HttpServer` for `LeyoChatService`
  - `WebEngineWidgets` for web document and file-exchange views
  - `Quick` and `QuickControls2` for the graphical installer shell
- Inno Setup 6 for Windows installer packaging
- Python 3 and Pillow only when regenerating project-owned bitmap assets

Qt is not vendored. Install it separately and pass its installation prefix to
CMake.

## Build

Open an x64 Native Tools command environment for Visual Studio 2022, then run:

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 `
  -DCMAKE_PREFIX_PATH="C:\Qt\6.6.3\msvc2019_64" `
  -DLEYOCHAT_BUILD_TESTS=ON

cmake --build build --config Release --clean-first --target LeyoChat
```

When Qt HttpServer is available, build the server components with:

```powershell
cmake --build build --config Release --clean-first `
  --target LeyoChatService LeyoChatServiceHost
```

The first configure is expected to report whether WebEngineWidgets and
HttpServer were found. Missing optional modules disable the corresponding
targets or UI features.

## Test

List configured tests:

```powershell
ctest --test-dir build -C Release -N
```

Run a focused test by name:

```powershell
ctest --test-dir build -C Release `
  -R LeyoChatRemoteChatServiceSettingsTests --output-on-failure
```

Run the complete configured suite only after all requested test executables
have been built:

```powershell
cmake --build build --config Release --clean-first
ctest --test-dir build -C Release --output-on-failure
```

## Optional message service

The client requires all three values before enabling service routing:

- Base URL, for example `https://chat.example.com`
- Bearer credential generated by the server installer
- Workspace ID allowed by the server configuration

The Windows server installer creates a random 64-character credential. Do not
commit a generated service configuration or share one credential outside its
intended deployment.

Detailed deployment instructions are in
[`docs/service-deployment.md`](docs/service-deployment.md).

## Optional file-exchange page

The WebEngine file-exchange page has no built-in endpoint. Set the following
environment variable before starting LeyoChat when the integration is needed:

```powershell
$env:LEYOCHAT_FILE_EXCHANGE_URL = "https://files.example.com"
```

Without this variable, the page stays local and reports that the service is not
configured.

## Packaging

Build the client installer:

```powershell
.\scripts\package-installer.ps1
```

Build the standalone server installer:

```powershell
.\scripts\package-server-installer.ps1
```

Both single-file installer scripts require the build directory to have been
configured with the graphical installer enabled:

```powershell
cmake -S . -B build-msvc -G "Visual Studio 17 2022" -A x64 `
  -DCMAKE_PREFIX_PATH="C:\Qt\6.6.3\msvc2019_64" `
  -DLEYOCHAT_BUILD_INSTALLER=ON
```

`package-windows.ps1` and `package-server-windows.ps1` remain available when
only the inner Inno Setup installer is required.

Packaging scripts perform clean target builds and stage third-party license
notices with the application. Binary distributors remain responsible for the
license obligations of their Qt build, including Qt WebEngine credits when
WebEngine is shipped.

## Repository layout

```text
src/            Client, launcher, service, networking, storage, and UI code
tests/          Qt and script-based tests
third_party/    Vendored source dependencies and their licenses
resources/      Project-generated backgrounds and call sounds
stickers/       Project-generated default sticker pack
installer/      Qt Quick installer shell
windows/        Windows resources and Inno Setup templates
scripts/        Build and packaging automation
tools/          Pressure model and reproducible asset generator
docs/           Service deployment and capacity guidance
```

Default media is generated by
[`tools/generate_open_source_assets.py`](tools/generate_open_source_assets.py).
The generator uses only geometric primitives and deterministic parameters.

## Security

Read [`SECURITY.md`](SECURITY.md) before exposing the service outside a trusted
network. In particular, the current P2P path does not bundle deployment TLS
credentials, service HTTP endpoints should be placed behind TLS, and some
optional integration credentials are currently stored in local Qt settings.
